Retries are disabled. Each test resets only the loopback test app's process-local
rate-limit fixtures; production limit implementations and values are unchanged.
The reset/status endpoints are attached solely by backend/e2e_server.py, never by
app.main. The production application cannot expose these endpoints.

ISOLATION
Pytest installs the guard before collecting tests. E2E and benchmark entry points
install the same guard before loading the app. Python dotenv loading is disabled;
provider/database credentials are removed. Socket DNS/connect/connect_ex and
libpq connections are checked. PostgreSQL must use loopback and the explicit
admin or disposable test database names. Subprocess migrations inherit the guard.
Unexpected attempts are recorded and fail pytest/E2E even if app code catches the
network exception. Optional public intelligence is mocked unavailable by default.
Browser and API-request fixtures allow only HTTP/WS loopback ports 8010 and 4173.
API redirects are disabled; service workers are blocked; browser requests and
WebSockets are intercepted. Safely fulfilled local route mocks need no external
network. CORS is not used as a safety boundary.

LIMITS
The test boundary protects normal repository entry points, not malicious test
code deliberately undoing the guard or arbitrary native networking libraries.
Short local benchmarks are not Linux-container peak-memory or long-soak proofs.
